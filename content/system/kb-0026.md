## Summary

The Terminal is a command line for operators who prefer the keyboard. Everything it does can also be done from the desktop. Commands are not case-sensitive. Every command entered is recorded in the audit trail with its arguments, whether or not it succeeds. Use of the Terminal is governed by :x[OSC-DIR-0301].

Open it from **Directory > Terminal**.

## Keys

| Key | Action |
|---|---|
| Enter | Run the command |
| Up / Down | Step through the commands entered this session |
| Tab | Complete a command name or a document number |
| Ctrl+C | Abandon the line, or stop a command that is paging |
| Space / q | Next page / leave the pager, when output is longer than the window |
| Ctrl+K | Search. Inside the Terminal, Ctrl+K is passed to the Terminal and does not open search |

## Documented commands

| Command | What it does |
|---|---|
| `help` | Lists the commands in this article, one line each. |
| `man <command>` | Shows the full entry for a command, e.g. `man find`. |
| `whoami` | Shows your operator ID, personnel number, tier, site, division and the time your session opened. |
| `clearance` | Shows your tier and the compartments you hold, with the date each was granted. |
| `sites` | Lists the facilities you are permitted to see, one line each: identifier, class and status. The list is filtered by your access. |
| `site <id>` | Shows the registry summary for one facility, e.g. `site ALPHA-03`. You are refused for a facility you are not permitted to see. |
| `rail status` | Shows the status of each rail segment and regional tram network in words, as published by Transit Operations. |
| `find <term>` | Searches the same index as Ctrl+K and lists the first twenty results with document numbers. |
| `open <docno>` | Opens a document in a new window, e.g. `open OSC-DIR-0412`. Refusals are shown as they would be on the desktop. |
| `mail` | Lists your inbox, newest first: message number, precedence, sender, subject. `mail <n>` opens message n. |
| `audit tail` | Shows the last twenty entries in your own workstation audit trail. |

### Example

```
> whoami
OPERATOR   OPR-A01-0402
PERSONNEL  P-3-05-0402
TIER       3
SITE       ALPHA-01
DIVISION   IAD
SESSION    1412Z (1012 EDT)
> clearance
TIER       3
HELD       none
> open OSC-DIR-0412
Opened OSC-DIR-0412 in Directives.
```

The operator shown is a test account.

## audit tail

`audit tail` prints entries in the form the security office keeps them: entry reference, time in Zulu and site-local, kind of activity, operator, workstation and a description. The command shows your own trail only. It cannot be pointed at another operator's ID.

:::redact{tier=2 auth="CMS" ref="CMS-08-0031"}
Supervisors of record at Tier 2 may run `audit tail <operator ID>` against an operator for whom they are the supervisor of record. The subject's trail records that it was read, and by whom.
:::

Entries cannot be deleted or amended from the workstation. If you believe an entry is wrong, report it to your site security office, not the Service Desk.

## Things the Terminal does not do

- It does not run programs, scripts or files. There is no file system to browse.
- It does not reach anything outside MERIDIAN. There is no external connectivity of any kind.
- It does not send mail. `mail` reads only; use Message Traffic to compose.
- It does not change your access. A refusal in the Terminal is the same refusal you would see on the desktop and cites the same directive.

## Reporting problems

If a documented command returns `UNKNOWN COMMAND`, check the spelling with `help`. If a documented command returns nothing at all, note the time and call the Service Desk on ext. 1-7700.
